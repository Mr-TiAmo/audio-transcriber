# 低置信标亮误报分析与优化探索（2026-11-08）

## 1. 实测现状

数据：`bench_10min`（`run_f90f68afb796`），去重后 2209 个有效字符，
与 LiPS 参考文本做字符级对齐（数字统一为阿拉伯写法后）：

| 指标 | 值 |
|---|---|
| 真实错误字符 | 33（1.49%） |
| 当前标亮字符 | 87 |
| 命中（TP） | 20 |
| 精确率 | **23.0%** |
| 召回率 | **60.6%** |

即标出的 4 个字里约 3 个是正确的，与用户观察一致。

## 2. 为什么正确字被标

### 2.1 预算大于错误量（结构性上限）

当前策略 `select_low_conf` 是**全局预算制**：按全片信息字符的 4% 标亮，
`bench_10min` 约 88 字。而真实错误只有 33 字，即使排序完全正确，
也至少有 55 个字必然是误标，精确率上限只有 33/88 ≈ **37%**。

### 2.2 entropy 衡量"模型不确定"而非"错误"

字符 entropy 分桶后的真实错误率：

| entropy | 字符数 | 错误率 |
|---|---|---|
| 0.0–0.1 | 1957 | 0.36% |
| 0.1–0.2 | 77 | 0.00% |
| 0.2–0.3 | 32 | 9.38% |
| 0.3–0.5 | 51 | 5.88% |
| 0.5–0.7 | 61 | 11.48% |
| 0.7–1.0 | 12 | 33.33% |
| ≥ 1.0 | 19 | 47.37% |

信号方向是对的（高熵区错误率是低熵区的 100 倍），但**高熵区正确字仍占一半以上**：
「的、和、到、演、节、源、人」这类字在口语里候选多、模型分布平，天然高熵。

### 2.3 只标「单字 token」，词内错误标不到

- 单字 token：605 字，错误率 3.97%；
- 多字 token：1604 字，错误率 0.56%（整词共享一个熵，标一个会误标整词）。

33 个错误中，单字 token 占 24 个（召回 60.6% 主要来自这里），
多字 token 占 9 个，当前策略**完全不标**。用户看到的"单字错误不标识"
主要指这一类：错误在词里，但词不对应单字 token。
反过来，标亮的单字往往落在词中某个字上（如"演"在"演进"里），
看起来像"词语被标了"。

## 3. 方案

### 3.1 立即可做：精度优先参数

`--low-conf-ratio 0.01 --low-conf-floor 0.8`（或直接改服务层默认）：

| ratio / floor | 标亮字数 | 精确率 | 召回率 |
|---|---|---|---|
| 4% / 0.1（旧默认） | 87 | 23.0% | 60.6% |
| 2% / 0.5 | 44 | 34% | ~45% |
| **1% / 0.8（新默认，已实施）** | **16** | **43.8%** | **21.2%** |
| 1% / 1.2 | 13 | 50% | 20% |

说明：把"标亮预算"改为"绝对分数阈值 + 上限"，宁可少标、标了就准。
代价是漏报增加，但页面标亮本来就只用来提示重点复核，误标多反而失去信任。

**已实施**：`DEFAULT_MAX_RATIO = 0.01`、`LOW_CONF_SCORE_FLOOR = 0.8`，
bench 实测标亮 87→16 字，P 23.0%→43.8%、R 60.6%→21.2%（TP 7/16）。
真实运行 `run_59b4778cf732` 标亮 16 字，与 bench 扫描一致。

### 3.2 词级聚合（改善可读性，不提升精确率）

把单字候选扩展到完整词（jieba 分词）：

| 方案 | 标亮字数 | 字级 P |
|---|---|---|
| 保持字符级 | 87 | 23.0% |
| 候选扩展到整词 | 132 | **15.9%** |
| 词级平均熵 top 1%（12 词） | ~44 | 35%（词级命中 50%） |

结论：整词扩展会让误报更多，不建议默认开启。若要做词级，只对
「词内 ≥ 2 个候选」或「词级分数超过阈值」的词整词标亮。

### 3.3 更强的独立信号（需实验）

单靠 entropy 的精确率天花板约 35–50%，要再提升需要新信号：

1. **第二模型交叉验证**（用户此前选定、尚未启动）：对同一音频跑
   FunASR Paraformer（快、RTF 低），两模型不一致处作为高精度候选。
   预期精确率显著高于单模型熵，代价是整片多一次推理。
2. **采样一致性**（已有 `--low-conf-mode quality` 与 `--sample-check N`）：
   对每段额外采样 N 次解码，一致性低的字符更可疑；成本 ×(N+1)，
   只对候选段采样可控制成本。
3. **强制对齐时长异常**（已有 `--low-conf-mode recall`）：对齐时长
   偏离该段分布（吞字、连读）时加权；`bench` 上单独效果未量化，
   可作为融合特征。
4. **词级语言模型重打分**：用更大中文 LM 对文本打分，找低概率词，
   对同音/近形错误（entropy 低但错）更有效。

### 3.4 校准

用离线数据拟合 `P(错误 | 特征)`，按目标精确率选阈值，替换当前
「固定 4% 预算 + 手动 floor」的启发式；同时保留一个显式的
"最多标 N 个"上限，避免长音频标亮过多。

## 4. 建议顺序

1. 先切精度优先参数（3.1，半小时内可验证）；
2. 用 `backend/scripts/confidence_word_explore.py` 在 bench 上对比
   第二模型交叉验证与采样一致性（3.3）；
3. 确认信号有效后再做融合与校准（3.4），词级聚合最后考虑。

## 5. 实施记录（2026-11-08）

- **已完成**：3.1 精度优先参数（`DEFAULT_MAX_RATIO=0.01`、

- **探索工具**：`backend/scripts/confidence_word_explore.py` 支持

  带特征的 dump：`backend/scripts/qwen3_asr_transcribe.py ... --dump-token-features`。

### 5.1 词级聚合实测（bench_10min）

| 方案 | 标亮字数 | 字级 P | 字级 R |
|---|---|---|---|
| 字符标亮扩到整词 | 132 | 15.9% | 63.6% |
| 保持字符级（当前） | 87 | 23.0% | 60.6% |
| 词级平均熵 top 1%（12 词） | 44 | 35.0% | 21.2% |

结论：整词扩展精确率反而下降，维持字符级；词级平均熵在同等召回下
精确率略高，但收益有限，暂不启用。

### 5.2 采样一致性实测（bench_10min，`--sample-check 2`）

命令：`--low-conf-mode quality --sample-check 2 --dump-token-features`，
产物 `data/bench/conf_sample/`。文本与基线略有差异（38 错 / 2205 字，
错误率 1.72%；基线 33 错 / 2209 字，1.49%）。

`sample_agree`（与 2 次额外采样的一致比例）分桶：

| sample_agree | 字符数 | 错误率 |
|---|---|---|
| [0, 0.5) | 2 | 100% |
| [0.5, 1) | 58 | 15.52% |
| = 1 | 2145 | 1.26% |

方向正确，但作为独立信号偏弱：阈值 `agree < 0.75` 标 60 字，
P=18.3%、R=28.9%（同口径纯 entropy 1% 预算为 P≈44%/R≈29%）。

与 entropy 融合（`quality` = entropy + 0.8×(1−agree)，段门控 + 预算）：

| 预算 | 纯 entropy | quality 融合 |
|---|---|---|
| 1% | P 44% / R 29% | P 40% / R 26% |
| 2% | P 29% / R 37% | P 31% / R 39% |
| 3% | P 26% / R 50% | P 25% / R 47% |

结论：**融合没有稳定提升**，且成本明显——推理 68 s → 142 s
（RTF 0.11 → 0.24，约 ×2.1）。暂不启用 `quality` 模式，
维持 `balanced` + 1%/0.8。

### 5.3 第二模型交叉验证实测（bench_10min）

模型：FunASR Paraformer-zh + ct-punc（`models/funasr-paraformer-zh`、
`models/funasr-ct-punc`，共约 1.6 GB）。输出
`data/bench/conf_cross/funasr.txt`。

性能：推理 6.3 s / 599 s 音频，RTF 0.0104（Qwen 0.11 的约 1/10），
整片额外耗时约 +9%；相对参考文本自身错误率 2.12%
（Qwen 1.49%，即 FunASR 单模型略差）。

「两模型不一致」作为独立信号（归一化后字符对齐）：

| 信号 | 标亮字数 | 精确率 | 召回率 |
|---|---|---|---|
| 当前默认（entropy 1%/0.8） | 16 | 43.8% | 21.2% |
| 两模型不一致 | 35 | 40.0% | **42.4%** |
| 不一致 ∩ entropy 标亮 | 15 | 46.7% | 21.2% |
| 不一致 且 单字 token 且 entropy≥0.2 | 14 | **50.0%** | 21.2% |
| 不一致 且 单字 token 且 entropy≥0.8 | 8 | 50.0% | 12.1% |

融合排序（候选=单字 token + 段门控，score = entropy + 1.0×不一致）：

| 预算 | 纯 entropy | entropy + 交叉验证 |
|---|---|---|
| 1% | P 44% / R 33% | P 44% / R 33% |
| 2% | P 33% / R 48% | **P 37% / R 55%** |
| 3% | P 27% / R 61% | **P 29% / R 64%** |

结论：**交叉验证是有效信号**——召回从 21.2% 提到 42.4%，精确率只降
约 4 个百分点；与 entropy 融合后中高预算档 P/R 双升。代价是模型体积
1.6 GB、整片多一次推理（+9%，RTF 0.01）。已作为**默认开启**的增强
（`--cross-check auto`），并输出独立第二档标亮（见 5.4）；两模型同错处
无法发现，召回上限约 40–60%。

实现注意：`funasr_transcribe.py` 的模型目录解析已兼容
`backend/models` 与仓库根 `models/`，并优先选择含 `config.yaml` 的目录
（`backend/models/funasr-fsmn-vad` 只有 snapshots 空壳，会让 FunASR 报
model not registered）。

### 5.4 落地实现（`--cross-check`）

链路：

1. **信号**：`local_asr.asr.confidence.cross_model_flags(hyp, other)`
   两侧先做数字归一化（`二零零八` → `2008`）与标点/空白剥离，再按
   Levenshtein 对齐；hyp 侧替换/插入算不一致，语气词差异按规则 v2 忽略。
   返回与 hyp 等长的 bool 数组。
2. **打分**：`CharSignal.cross_mismatch` + 常量 `CROSS_BONUS = 1.0`，
   `score_signal` 对全部档位统一加分，参与预算内排序。
3. **独立第二档**：`select_low_conf` 中不一致字符**不受段门控与分数
   下限约束**（两模型不同处往往熵不高，走常规门控会漏），按
   `CROSS_MAX_RATIO = 0.05` 安全上限追加；与常规预算去重，总标亮量
   ≤ 预算 + 5%。**关键：交叉字符不参与常规预算竞争**——`CROSS_BONUS`
   会让它们挤掉纯 entropy 的高价值候选（实测 P 52%→27%），第二档
   本身已覆盖它们，常规预算应继续留给 entropy 独有信号。
4. **坐标映射**：`build_cross_flags()` 把合并全文坐标映射回各 chunk
   原文坐标（`CharSignal.index` 口径）——去重会裁掉下一段开头/上一段
   结尾的字符，必须按 `apply_dedup_to_texts` 的结果顺序定位，否则加分
   落在错误的字上（单测 `test_cross_check.py` 锁定）。
   另有两层「归一化坐标」陷阱：`normalize_numbers` 会压缩数字串
   （「一百二十三」→「123」），对齐发生在归一化文本上，映射回原文必须
   `num_map[keep[hi]]`；漏掉 `keep` 这一层会让标记整体右移（实测标亮
   与不一致字符几乎完全错位、P 从 52% 掉到 24%）。数字串内部无法定位
   具体哪一位，统一整串标记（单测
   `test_cross_model_flags_positions_after_number_compression` 锁定）。
5. **入口**：ASR 脚本 `--cross-check auto|<第二模型文本>`；`auto` 现场
   调用 `funasr_transcribe.py --model paraformer-zh`，任何失败只告警并
   降级为纯 entropy，不阻塞主转写。服务层 `task_service` **仅对
   ≥10min 的长音频**默认传 `cross_check="auto"`（FunASR 子进程有约
   48 s 固定开销，短音频不划算）；`OrchestrationOptions.cross_check`
   与 CLI `--cross-check` 供编排层透传，可手动强制开启。
6. **stats 记录**：`low_conf.cross_check = {enabled, source, mismatch_chars,
   seconds}`，便于复盘。

### 5.5 落地后实测（bench_10min，`--forced-aligner --cross-check`）

与 5.3 同一次转写口径对比（有效字符 2205，真实错误 38，错误率 1.72%）：

| 方案 | 标亮字数 | 精确率 | 召回率 |
|---|---|---|---|
| 纯 entropy 1%/0.8（同 run 重放） | ~24 | 44% | 29% |
| 1% 预算 + 交叉加分（无第二档，交叉挤占预算） | 25 | 52.0% | 34.2% |
| 仅交叉验证（不一致全标） | 42 | 52.4% | 57.9% |
| **落地：常规预算 ∪ 交叉第二档** | **58** | **43.1%** | **65.8%** |

44% 持平），远高于旧默认 4% 预算的 23%。实现上任何失败都降级为纯
entropy，不影响主流程。

CLI 可手动强制。进一步优化（复用 VAD、主进程内加载）暂不做。

## 6. 2026-11-10 交互调整：词级标亮 + 交叉验证页面开关

用户确认的两项调整（取代上文 §5.4/§5.5 的交互口径）：

1. **标亮粒度由单字改为词组/词语**：`select_low_conf()` 选出字符后，
   用 jieba 分词把每个候选扩展到所在词边界再合并
   （`expand_positions_to_words`）。输出仍是 `[[start,end],...]` 字符
   区间，`segment_service` 的切片/去重平移与前端 `<mark>` 渲染不变。
   §5.1 历史实测整词扩展会把字符级精确率从 23.0% 降到 15.9%，这是
   用户明确选择的“可读性优先”取舍。
2. **交叉验证改为页面可选、默认关闭**：转写请求新增 `crossCheck`
   （默认 `false`），`TaskBar.vue` 增加「交叉验证」复选框；删除
   `task_service` 中“音频 ≥10min 自动启用”的逻辑。勾选后 FunASR 仍
   整片转写（约 30–48s 固定开销），但结果**不参与选词、不再作为第二档
   追加**，只核验已选出的低置信词：词内全部一致 → 取消该词标亮；
   存在不一致 → 保留整词。第二模型缺失/失败时视同未勾选。
3. **测试**：`test_confidence.py` 新增词级扩展、交叉核验（一致取消/
   不一致保留/不追加词外字符）用例；`test_model_selection.py` 覆盖
