# 低置信标亮策略调优（bench_10min 实测）

日期：2026-11-07
结论：旧策略「每段 top-10% 高熵字符标亮」精确率仅 15.6%，与用户观察一致；
新策略「仅单字 token + 熵阈值 + 段级门控」把精确率提升到 33.3%，标亮量减少 70%。

## 1. 问题

用户反馈：页面橙色标亮的字符，与音频核对后大多数是正确的。

## 2. 测试方法

- 音频：`data/bench/bench_10min.wav`（LiPS 66 条拼接，599.1 s）
- 参考：`data/bench/bench_10min_reference.txt`
- 对账：逐段 `conservative_norm` → `align_ops`（Levenshtein 回溯）→
  `apply_filler_rules`（语气词等价），得到每个转写字符的 正确/错误 标签
- 指标：标亮字符中的精确率（P）、真实错误字符的召回率（R）
- 本次重跑：2220 个归一化字符，真实错误 83 个（3.74%）

## 3. 旧策略结果

| 项 | 数值 |
|---|---|
| 标亮字符 | 218 |
| 命中 TP | 34 |
| 误报 FP | 184 |
| 漏报 FN | 49 |
| 精确率 | **15.6%** |
| 召回率 | **41.0%** |

随机基线约 3.7%（全部错误率）。所以熵排序确实有效（4.2 倍富集），
但 15.6% 意味着"标亮里 5/6 是正确的"，用户体验不可接受。

### 根因

1. **标亮比例（10%）远高于错误率（3.74%）**：即使把标亮字符随机撒在全文，
   精确率上限也只有约 37%；固定比例策略在数学上就不可能"标亮的基本都错"。
2. **每段各自 top-10%**：模型在某段很确定（段 1 仅 2 错、段 2 仅 6 错）时，
   仍被强制标出 22-23 个字符，几乎全是误报（该两段命中为 0）。
3. **token 粒度稀释**：见下节，多字 token 的字符被整词标亮，而它们几乎不错。

## 4. 关键发现：token 长度比熵更有区分力

Qwen3-ASR 的 BPE 会把高频词合成一个 token。按 token 长度分层统计：

| token 类型 | 字符数 | 错误数 | 错误率 |
|---|---|---|---|
| 单字 token | 615 | 62 | **10.08%** |
| 多字 token（2 字及以上） | 1605 | 21 | **1.31%** |

单字 token 的错误率是多字 token 的 7.7 倍。直觉解释：模型把多个字合并输出
表示它对整个片段很有把握；逐字输出往往发生在犹豫、生僻词、数字/专名处。

旧策略按字符熵排名，而同一 token 内所有字符共享同一个熵值——多字 token 一旦
熵偏高，整个词都被标亮，这是误报的主要来源之一。

## 5. 熵信号本身的校准

按全局熵百分位分桶（正例 = 错误）：

| 熵区间 | 字符数 | 错误率 | 占全部错误 |
|---|---|---|---|
| P0-P50 | 1109 | 2.43% | 32.5% |
| P50-P80 | 667 | 2.55% | 20.5% |
| P80-P90 | 221 | 3.62% | 9.6% |
| P90-P95 | 112 | 6.25% | 8.4% |
| P95-P97 | 43 | 16.28% | 8.4% |
| P97-P99 | 45 | 17.78% | 9.6% |
| P99-P100 | 23 | **39.13%** | 10.8% |

- 字符级 AUROC 0.662 / AP 0.152（正例率 0.037，约 4 倍提升）。
- `neg_logprob`、`neg_margin` 与 entropy 高度相关，融合无增益。
- **32.5% 的错误落在熵最低的一半字符里**——模型对这些同音/近形替换非常自信，
  单靠熵无法发现。这是召回率的硬上限。

## 6. 新策略

实现于 `backend/scripts/qwen3_asr_transcribe.py::_compute_low_conf_spans`：

1. 只考虑**单字 token**（多字 token 整词跳过分词，避免整词误报）；
2. 熵 ≥ 0.2（过滤模型已收敛的常规字）；
3. **段级门控**：本段单字 token 的最高熵 < 0.7 时整段不标（模型全程确定）；
4. 相邻字符合并为区间写入 `low_conf_spans`。

### 效果对比

| 策略 | 标亮数 | 命中 | 精确率 | 召回率 |
|---|---|---|---|---|
| 旧：段内 top-10% | 218 | 34 | 15.6% | 41.0% |
| 新：单字 token + ent≥0.2 | 77 | 23 | 29.9% | 27.7% |
| **新 + 段级门控** | **66** | **22** | **33.3%** | **26.5%** |
| 参考：仅熵≥0.9（全局） | 23 | 9 | 39.1% | 10.8% |

新策略每 10 分钟音频标约 66 个字符（每段 0-18 个，零错误段为 0），
精确率翻倍，标亮量减少 70%。

## 7. 局限与后续

- **同音/近形错（多为替换）无法发现**：占错误的 32.5%，模型熵极低。
  进一步提高召回需要更强的信号，候选：
  - 二次推理 n-best 分歧（探针实测字符级 AP 0.24，优于熵；代价约 2 倍推理）；
  - 更大模型（1.7B）或上下文纠错。
- **多字 token 内的错误**（21 个，25%）不在标亮范围内；若强行标亮会大幅拉低精确率。
- **段尾/切块边界错误率显著偏高**：段内位置 90-100% 区间的错误率 11.4%，
  其他区间 1.8%-6.3%。原因是 VAD 切块/重叠拼接在边界处的截断与丢字，
  属于切块策略问题，值得单独优化（而不是靠标亮提示）。
- 阈值 0.2 / 0.7 来自本 bench（83 个错误）的调参，样本量有限；
  换模型或语言时应重新对账。

## 8. 复现

```bash
# 1) 重跑 ASR 并导出逐字符熵（调试开关，生产不开启）
python scripts/qwen3_asr_transcribe.py \
  --model ../models/Qwen3-ASR-0.6B \
  --audio ../data/bench/bench_10min.wav \
  --output ../data/bench/analysis/bench_10min_raw.txt \
  --device cuda --language Chinese --segmentation auto \
  --batch-size 4 --batch-max 4 --chunk-strategy balanced \
  --target-chunk 60 --balance-tolerance 0.1 \
  --vad-model ../models/funasr-fsmn-vad --dump-token-features

# 2) 对账（读 stats.json 的 low_conf_spans）
python scripts/confidence_audit_bench.py ../data/bench/analysis/bench_10min_raw.stats.json

# 3) 阈值扫描 / 信号诊断 / 派生特征实验
python scripts/confidence_threshold_sweep.py <stats.json>
python scripts/confidence_diagnostics.py <stats.json>
python scripts/confidence_experiments.py <stats.json>
```
