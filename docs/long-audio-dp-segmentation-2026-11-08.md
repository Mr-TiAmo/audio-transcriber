# 长音频动态规划分段（2026-11-08）

## 1. 背景

原有两种切分策略：

- `silence`：从当前块起点贪心寻找最长静音切一刀。实现简单，但块长完全由静音分布决定
  （60 分钟真实音频上块长 15.6–180 s，标准差 55.8 s），batch 推理时 padding 严重。
- `balanced`：先按总时长均分块数，再把每个理论切点吸附到附近静音。块长均匀
  （标准差 4.4 s），batch 效率高；但每个切点只看自己附近的停顿，局部最优会累积，
  60 分钟音频上仍有 33 刀吸附失败（硬切 33/58）。

`dp` 策略把整段音频的切点作为一个整体求最优：在「块长偏离目标」与「切点是否落在
静音上」之间做全局权衡，避免逐点贪心导致的后段边界恶化。

## 2. 算法

状态与节点
- 节点 0 = 音频起点，节点 n = 音频终点（`total_ms`）。
- 中间候选点 = **全局所有 VAD 停顿的中点**（停顿长度 ≥ `balance_min_silence_ms`），
  外加均分理论边界 `round(total_ms * i / n)` 作为兜底（必定可硬切）。

状态转移
- `dp[j]` = 到达节点 j 的最小累计代价。
- 对每个 i < j，若块长 `length = pos[j] - pos[i]` 满足
  `min_len ≤ length ≤ max_len`，则

  ```
  cost = dp[i] + ((length - target) / target)²
                  + (切点是否静音 ? -dp_gap_bonus * min(gap, 1000) / 1000
                                  : +dp_forced_penalty)
  ```

  最后一段不加硬切惩罚（终点无需切）。
- 块长约束：`min_len = max(1000 ms, target * 0.5)`，
  `max_len = min(max_chunk_seconds, target * 1.8)`。
- 记录前驱，结束后回溯得到切点序列；找不到可行路径时回退 `plan_balanced_cuts`。

复杂度：候选点数 = VAD 停顿数 + 理论边界数（60 分钟约 180 个），O(k²) 可忽略。

## 3. 参数

| 参数 | 默认 | 含义 |
|---|---|---|
| `dp_forced_penalty` | 0.3 | 硬切（未落在静音上）的代价，量级与「块长偏离²」可比 |
| `dp_gap_bonus` | 0.15 | 切在静音上的奖励，gap 按 1 秒封顶归一 |

CLI：`--dp-forced-penalty` / `--dp-gap-bonus`（`qwen3_asr_transcribe.py`）。
评估脚本：`backend/scripts/bench_dp_cuts.py`，支持 VAD 缓存与权重扫描。

## 4. 实测

数据：`data/bench/bench_60min.wav`（3540 s，VAD 127 段），目标块长 60 s。

| 策略 | 块数 | 最短 | 最长 | 均值 | 标准差 | 吸附率 | 硬切 | 覆盖 |
|---|---|---|---|---|---|---|---|---|
| silence | 37 | 15.6 | 180.0 | 95.7 | 55.82 | 69.4% | 11 | 是 |
| balanced | 59 | 43.3 | 72.6 | 60.0 | 4.39 | 43.1% | 33 | 是 |
| dp (f=0.2, b=0.15) | 57 | 42.2 | 85.5 | 62.1 | 7.59 | 62.5% | 21 | 是 |
| **dp (f=0.3, b=0.15)** | **56** | **42.2** | **92.8** | **63.2** | **8.53** | **63.6%** | **20** | 是 |
| dp (f=0.6, b=0.15) | 55 | 36.8 | 104.4 | 64.4 | 13.82 | 70.4% | 16 | 是 |
| dp (f=1.2 / 2.0, b=0.15) | 55 | 36.8 | 104.4 | 64.4 | 13.82 | 70.4% | 16 | 是 |

其他场景：

- 5 分钟（`random5m/random1.wav`，12 个 VAD 段）：balanced 与 dp 结果完全一致
  （5 块，std 5.72，吸附率 50%），说明短音频上 DP 不产生额外收益。
- 稀疏合成（25 s 句 + 300 ms 停顿）：balanced 59 块 / std 5.53 / 吸附 60.3% / 硬切 23；
  dp 70 块 / std 3.43 / 吸附 **100%** / 硬切 0。停顿充足时 DP 可做到零硬切。

解读
- `f` 从 0.6 提到 2.0 结果不变：硬切惩罚已不是主导项，瓶颈是候选停顿本身稀疏，
  继续加罚只会让 DP 更倾向理论边界（块长反而更不均），因此默认取 **0.3**。
- 静音奖励 `b` 在 0–0.15 之间对结果影响很小（±0.2 s 标准差），保留 0.15 即可。
- DP 用块长均匀度换静音吸附率：吸附率 43%→64%、硬切 33→20，
  代价是块长标准差 4.4 s→8.5 s。batch=4 时仍远低于 `max_chunk` 上限。

## 5. 启用方式

- CLI：`--chunk-strategy dp`（长音频推荐，配合 `--target-chunk 60`）。
- 服务层：`task_service` 对 **>10 分钟**的音频自动使用 `dp`，其余用 `balanced`
  （10 分钟阈值与 V3.0 §5 的长音频定义一致）。
- `--strategy adaptive` 目前仍只在 silence/balanced 之间决策，不自动切到 dp；
  需要 DP 时用 `--strategy manual --chunk-strategy dp`。

## 6. 块重叠：0.5 s → 1.5 s（V3.0 §5 设计漂移）

V3.0 §5 设计每块两侧扩展 0.5 s 重叠，实测不够用：

- 切点落在词中时，0.5 s 只能让下一块听到半个词（「至」/「然」），ASR 会各自补出
  一个完整句子，拼接后出现断词；
- 重复内容通常不足 4 字（「英国」/「英国人」），低于 `align_boundary` 的
  `min_overlap=4`，去重完全失效。10 分钟音频上 dedup 只有 2 条，多数边界裸露。

改为 **1.5 s** 后同一音频：

| overlap | 块数 | dedup 条数 | 段首标点 | 边界效果 |
|---|---|---|---|---|
| 0.5 s | 10 | 2 | 有（「概。」/「述」） | 断词多（「至。」/「然」） |
| 1.5 s | 10 | 9 | 0 | 基本通顺（「至二零零八年」完整） |

代价是每块多识别 3 s 音频（相对 60 s 块长约 5%），可接受。

## 7. 块边界伪标点清理

切点截断音频时，ASR 会给块末补一个句号/引号，下一块开头则可能带出续文的标点，
直接拼接会出现「运动概。/述」「……的。」/「人类……」这类错位标点。

规则（只在**确实发生去重**时执行，避免误删原文标点）：

1. 上一块尾部、下一块头部都有可清理标点 → 保留上一块标点，删下一块重复标点；
2. 只有上一块尾部有标点、下一块直接接字 → 删上一块尾标点（伪句末）；
3. 下一块头部无标点 → 不动。

可清理标点：`。！？；，、：!?;,:`；尾部额外包含右引号 `”’`（引语被截断时会残留半个）。
括号不在集合内，避免误删原文包裹符。

`merge_texts` 与 `apply_dedup_to_texts` 共用同一规则；`segment_service._dedup_offsets`
里同步平移 `[lo, hi)` 区间，保证 `low_conf_spans` / `aligned_tokens` 与裁剪后的文本
逐字符对齐。10 分钟实测：段首标点 0 段，9 个边界全部通顺。

## 8. 已知局限

- 候选点稀疏时（朗读/演讲，<3 gaps/min），DP 会被迫在少量停顿间选择，
  块长波动会明显大于 balanced；若 batch 效率优先，应继续用 balanced。
- 硬切代价与块长偏离项都是无量纲经验值，未做端到端 CER 对比；
  当前依据是边界质量（吸附率、硬切数）与 batch padding 的权衡。
- 末块不受 `max_len` 约束之外的额外处理；若结尾静音很长，DP 可能把最后一块拉长，
  由 `build_chunks` 的 `cut_silence_ms` 记录可追溯。
- 单字重复（「是」/「呈」）仍低于 `min_overlap=4` 无法去重；fuzzy 去重偶发多裁
  （把「，十」当重叠裁掉）。这两类需要更长的重叠或词级对齐才能根治。
